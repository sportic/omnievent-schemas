# OmniEvent platform crosswalk

This is the Phase 1 **design crosswalk**, not a claim that an adapter exists. Proposed OmniEvent field names are canonical-model recommendations. Platform cell prefixes are the required fidelity classes:

- `direct` — same concept and value can be copied.
- `transformed-lossless` — representation changes, source meaning/value is retained.
- `lossy` — one side cannot represent all information or requires aggregation.
- `extension-only` — the receiving platform has no demonstrated native field.
- `unsupported` — verified API surface has no such capability.
- `unverified` — accessible evidence does not establish the field/capability.

`—` means there is no specific platform claim; source links support adjacent verified coverage. For fields with no verified contract, use `unverified`, not a guess. Sources are first-party references except where a line is expressly labeled product help.

Classification is per platform, so each platform cell carries the explicit fidelity token. The final column indicates that there is no single aggregate fidelity class for that concept.
